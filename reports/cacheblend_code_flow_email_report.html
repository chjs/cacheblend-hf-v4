Executive Summary
  • 이 repository 는 CacheBlend (EuroSys '25, paper §4 selective KV recompute) 알고리즘을 HuggingFace Transformers 위에 재구현한 v4 이다. 원본 구현은 YaoJiayi/CacheBlend (vLLM fork) 와 LMCache/LMCache (vLLM plugin).
  • 핵심 라이브러리 코드는 src/cacheblend/ 11 개 파일 (~1,650 LOC). 메인 알고리즘 모듈은 fusor.py (4 fuse 함수) + hkvd.py (deviation 측정) + kv_store.py (chunk 단위 캐시).
  • 2 개의 selective recompute 구현이 공존: (1) fuse_selective (v4 초기, full forward + K/V hook merge), (2) fuse_selective_lmc_parity (sparse forward, paper §4 / LMCache 1:1 등가).
  • 실험 드라이버는 benchmarks/ 아래: Phase 6/7 (Musique), Loong cache-then-reverse, CacheBlend 공식 스크립트 포팅.
  • 대상 모델: Mistral-7B-Instruct-v0.2 + Llama-3.1-8B-Instruct. attention impl 은 eager 기본 (Phase 0-7 bit-exact 검증) / sdpa 옵션 (long context).
  • 검증된 것: paper §4 의 (a) pre-RoPE 저장 + retrieval 시 RoPE shift, (b) HKVD 수식, (c) top-K 선정, (d) sparse forward semantics, (e) Mistral Musique F1, (f) Llama-3.1-8B Loong F1 + HKVD boundary enrichment 3.13x. CPU 단위 테스트 8/8 PASS.
  • 아직 검증 필요: LMCache (vLLM) 바이너리 와의 prefill 결과 비트 비교 (인프라 부재로 불가능), Llama-3.1-8B Musique 의 CacheBlend < FullReuse 원인 (모델 의존성 vs 추가 버그).
  • 이메일/PR 본문 으로 그대로 붙여 넣을 수 있는 self-contained HTML.

2. CacheBlend 기본 개념 (처음 보는 사람용)

2.1. KV cache 는 무엇이고 왜 중요한가

Transformer 의 attention 은 매 token 마다 모든 이전 token 의 Key (K) 와 Value (V) 를 참조한다. 한번 prefix 를 처리하면서 계산된 K/V 를 보존해 두면 다음 호출 에서 재계산을 피할 수 있다. 이를 KV cache 라고 부른다. vLLM/HF DynamicCache 등이 이를 구현한다.

2.2. 왜 chunk 순서가 바뀌면 단순 KV cache 재사용이 깨지는가

RoPE (Rotary Position Embedding) 가 적용된 K 는 "이 token 의 position 이 p" 라는 정보를 포함한다. Document A 를 position [0..100] 에서 prefill 하면 그 K 는 그 position 에 묶인 회전이 들어가 있다. A 를 새 prompt 의 position [500..600] 에 끼워 넣으면 RoPE 가 어긋나 attention 이 무의미해진다. 또한 chunk-local prefill 동안에는 다른 chunk 와의 cross-chunk attention 이 없었으므로 hidden_state 도 다르다 — 이 차이는 RoPE 와 무관하게 발생한다.

2.3. CacheBlend 가 이 문제를 해결하는 방식 (paper §4)

  1. RoPE shift 또는 pre-RoPE 저장 + 재적용 으로 position mismatch 해소.
  2. cross-chunk attention 으로 인한 hidden_state 차이의 정확한 보상은 비싸지만, 각 token 에 대한 "fresh K (cross-chunk attention 후) vs cached K (chunk-local)" 의 deviation 을 계산하면 차이가 큰 top-K token (HKVD) 만 fresh forward 가 의미. 나머지는 cached K/V 그대로 둠.
  3. check_layer 에서 한번 deviation 측정 → top-K 선정 → 그 token 들만 후속 layer 에서 sparse forward 로 다시 계산. ratio 0.15 (15% recompute) 가 paper 의 default.

2.4. 우리 구현 의 접근 (HF Transformers 친화적)

  • v4 초기 (fuse_selective) 는 HF 친화적 hook 디자인: full forward 유지하되 k_proj/v_proj output 의 non-HKVD position 만 cached 값으로 override. 코드 침습 최소.
  • 이후 LMCache 1:1 비교에서 paper §4 의 sparse forward (Q 와 hidden_state 도 sparse) 와 의미적으로 다름을 발견. fuse_selective_lmc_parity 추가 — HF DecoderLayer 의 sub-module 을 manual 호출해서 check_layer 부터 Q[top_indices]/residual[top_indices] 슬라이싱 + sparse Q × full mixed K/V eager/SDPA attention. past_key_values 는 full-length 유지 (decode 호환).

5. 주요 코드 파일 상세 분석

5.1. src/cacheblend/model.py — LayerwiseModel

  • 역할: HF causal LM 을 wrapping. layer-by-layer forward 접근 + 매 layer 의 pre-RoPE K capture 를 제공.
  • 주요 메서드: embed_tokens, compute_position_embeddings, build_causal_mask, prefill_layer(layer_idx, hidden_states, ...), final_norm_and_lm_head, forward_layerwise(input_ids), get_pre_rope_k(layer_idx).
  • 외부에서 호출: 모든 fuse_* 함수 + precompute_* 함수가 진입점.
  • 내부: __init__ 가 _install_k_proj_hooks() 로 매 layer.self_attn.k_proj 에 forward-hook 설치 → 호출 시 self._pre_rope_k[idx] = output.detach() 저장.
  • 입력: input_ids: torch.LongTensor (1, S), use_cache: bool.
  • 출력: LayerwiseOutput(logits=(1, S, V), past_key_values=DynamicCache).
  • CacheBlend 단계: Step A 의 forward + capture 기반 인프라.
  • 주의: attn_implementation="eager" 기본 (Phase 0-7 bit-exact 검증). long context 에서 "sdpa" 옵션 사용 (L45).
  • 헷갈리기 쉬운 점: HF 4.49 의 layer kwarg 는 past_key_value (singular). 우리 prefill_layer 도 singular 사용. plural 로 전달하면 silently **kwargs 로 빠져 cache 비어있게 됨 (LMCache parity 구현 도중 발견된 버그, commit a14660c).

5.2. src/cacheblend/fusor.py — 5 fuse 함수

  • 역할: 핵심 알고리즘. prefill 시 KV cache 를 어떻게 활용할지 결정.
  • 공통 boundary safe-shortcut (L13): ratio==0 → fuse_full_reuse, ratio>=1 → fuse_full_recompute, len(chunks)<=1 → fuse_full_recompute. 코드 경로 동일 보장 으로 max_diff=0.
  • fuse_full_reuse: 매 layer 별로 (1, total_seq, hidden_kv) 의 K_override / V_override 텐서 빌드 → chunk slice 채움 → k_proj.register_forward_hook(lambda: return K_override[li]). HF 의 apply_rotary_pos_emb 이 hook 결과에 fused position 의 RoPE 적용.
  • fuse_selective_lmc_parity (~376 LOC, fusor.py:298-674): 4 단계 — (1) boundary shortcut, (2) full K_stored_pre/V_stored 빌드, (3) layers 0..check_layer-1: full forward 표준 inner.layers[li](...), (4) layer check_layer: manual input_layernorm → q/k/v_proj → kv_deviation → top-K select → 마지막 position force-include → K mixed (cached@non-top + fresh@top) → SDPA(sparse Q × full mixed K) → o_proj → residual → post_attn_layernorm → mlp, (5) layers check_layer+1..end: manual sparse 동일 흐름. past_key_values 는 매 layer 에서 full-length 로 update.
  • 입력: layerwise_model, chunks (list[Chunk]), kv_store, recompute_ratio (float), check_layer (int).
  • 출력: 기본 logits, return_layerwise_output=True 시 LayerwiseOutput, return_hkvd_indices=True 시 추가 top_indices.
  • CacheBlend 단계: C/D/E/F.
  • 주의: fuse_selective (legacy) 와 fuse_selective_lmc_parity 는 다른 알고리즘 (L43). Phase 8 이후 default 는 후자.
  • SDPA + mask handling (L45): SDPA 사용 시 _update_causal_mask 가 None 반환 → 수동 (1,1,S,S) -inf-above-diagonal mask 생성. DynamicCache 의 K dim +1 padding → SDPA 호출 전 [:, :, top_indices, :total_seq] 슬라이스.

5.3. src/cacheblend/hkvd.py — HKVD 선정

  • 역할: token 별 KV deviation 계산 + top-K 인덱스 반환.
  • kv_deviation(K_new, K_old): 둘 다 fp32 cast → (K_new - K_old)**2 → sum(dim=-1) (hidden dim) → squeeze batch → (S,) per-token scalar.
  • select_top_k(deviations, ratio): topk_num = max(1, min(int(N*ratio), N)), torch.topk(largest=True), 결과 인덱스를 torch.sort 로 ascending (causal mask 호환).
  • 입력: pre-RoPE K (1, S, hidden_kv).
  • 출력: indices (int64, k 개, ascending).
  • CacheBlend 단계: E.
  • 주의: RoPE 의 회전 불변성 (squared L2 보존) 으로 pre/post RoPE 둘 다 결과 동일.

5.4. src/cacheblend/precompute.py — 2 cache population

  • precompute_chunk_kv(lw, chunk): 단일 chunk 의 token_ids 만 사용한 standalone forward. positions 0..L-1, no cross-chunk attention. v_proj 에 임시 hook → V capture. get_pre_rope_k(li) 로 K capture.
  • precompute_from_cache_prompt(lw, chunks_in_cache_order, skip_chunk_ids): 모든 chunk 를 한 fused input 으로 full forward → 매 layer 의 get_pre_rope_k 결과를 chunk offset 으로 slice → 각 chunk 별 entry 로 KVStore 저장. LMCache 의 cache-population 과 cross-chunk 정보 동등.
  • CacheBlend 단계: A.
  • 주의: Loong 처럼 chunk 순서 reverse 시 후자 사용 권장 (cross-chunk 정보 포함).

5.5. src/cacheblend/kv_store.py — LRU chunk cache

  • 역할: chunk_id 키 의 in-memory KV cache.
  • 주요 메서드: has(id) / get(id) / put(id, K_per_layer, V_per_layer) / evict_lru() / clear(). Phase 4 추가: prefetch_chunk(id, loader_fn) async (ThreadPoolExecutor).
  • 저장 형식: {"K": list[Tensor(1, L, hidden_kv)], "V": list[Tensor(1, L, hidden_kv)]} per layer.
  • CacheBlend 단계: A + B.
  • capacity: 기본 1024 chunks (OrderedDict 기반 LRU eviction).

5.6. src/cacheblend/rope.py — RoPE shift

  • apply_rope_shift(K_pre, target_positions, lw): pre-RoPE K 를 (B, num_kv_heads, S, head_dim) shape 으로 reshape → inner.rotary_emb 로 (cos, sin) 계산 → HF apply_rotary_pos_emb(dummy_q, K_heads, cos, sin) 호출. dummy_q 는 무시.
  • CacheBlend 단계: D.
  • 검증: benchmarks/verify_rope_recomputation.py 가 fuse_full_reuse 후 K 가 정확히 fused position 의 post-RoPE 임을 5 layer × 2 chunk 에서 비트 등가 (diff = 0.000e+00) 확인 (commit de6d818).

7. 주요 알고리즘 흐름 (코드 위치 중심)

7.1. Chunk handling

  1. Driver 가 prompt 를 list[str] 로 분할 (e.g., parts = [system, doc_1, ..., question]).
  2. chunker.chunk_texts(tokenizer, parts) 가 각 string 을 독립 tokenize → Chunk(text, token_ids, chunk_id).
  3. chunk_offsets(chunks) 가 fused 위치 (start, end) tuple 리스트 반환.
  4. fused_input_ids(chunks) 가 token_ids 를 concat → (1, total_seq) tensor.

7.2. KV cache construction

  1. precompute_chunk_kv(lw, chunk): chunk_only fused_input_ids → forward_layerwise → get_pre_rope_k(li) + v_proj hook capture.
  2. 또는 precompute_from_cache_prompt(lw, chunks, skip_chunk_ids): full forward → chunk_offsets 로 per-chunk slice.
  3. 결과를 kv_store.put(chunk.chunk_id, K_per_layer, V_per_layer).

7.3. KV cache reuse + RoPE handling

  1. fuse_* 함수가 layer 별 K_override (1, total_seq, hidden_kv) 빌드.
  2. 각 chunk 의 (start, end) 위치에 K_override[li][:, start:end, :] = entry["K"][li].
  3. k_proj.register_forward_hook(lambda: return K_override[li]) 로 fresh forward 의 k_proj 출력 을 K_override 로 대체.
  4. HF Mistral/Llama 의 apply_rotary_pos_emb 가 fused position_ids 로 자동 RoPE 적용 → post-RoPE K at fused positions.

7.4. Selective recompute (LMCache parity, fusor.py:298-674)

  1. Boundary shortcut 점검.
  2. K_stored_pre / V_stored 빌드 (full length).
  3. Layers 0..check_layer-1: 표준 inner.layers[li](past_key_value=past_kv, use_cache=True) 호출 → full forward, past_kv 에 fresh K/V 누적.
  4. Layer check_layer (manual): input_layernorm → q/k/v_proj → kv_deviation(k_full_pre, K_stored_pre[check_layer]) → select_top_k(devs, ratio) → force-include 마지막 position → K mixed = cached@non-top + fresh@top → RoPE apply → past_kv.update(k_mixed_post, v_mixed) → SDPA(q_sparse_post, k_mixed_post, v_mixed, mask=causal[:, :, top, :total_seq]) → o_proj → residual_sparse = residual_full[top] + attn_out → post_attn_layernorm + mlp (모두 sparse).
  5. Layers check_layer+1..end: hidden_state 가 sparse [topk_num] 인 채로 같은 manual 흐름 반복. K_full_li = cached_post (RoPE-shift via apply_rope_shift) + scatter fresh @ top. past_kv.update(k_full_li, v_full_li) — full-length 유지.
  6. Final: norm + lm_head on sparse hidden → logits_sparse → full-length zero tensor 의 top_indices 위치 에 scatter (마지막 position 항상 포함 보장).

7.5. Generation

  1. greedy decode loop: next_id = logits[0, -1].argmax().
  2. 매 step model(input_ids=next_id, past_key_values=past_kv, use_cache=True).
  3. EOS 또는 max_new_tokens 까지.
  4. torch.inference_mode() context 의무 (L40).

7.6. Evaluation

  1. per-row F1 (compute_f1_against_aliases) / Rouge-L.
  2. per_method 집계 (mean, median, zero_count, one_count, ttft_mean).
  3. paired bootstrap CI vs FullReuse (1000 회, seed=42).
  4. failure subset (FullReuse < FullRecompute) 별도 집계.
  5. prompt length buckets (0-8k / 8-16k / 16-24k / 24-32k / 32-64k / 64-128k).
  6. HKVD boundary enrichment (Loong/official): ±1, ±3, ±8 window 의 hkvd/all fraction + enrichment ratio.

8. 핵심 용어 미니 사전

KV cache
Transformer attention 의 Key/Value 텐서 보존. 한번 prefill 한 prefix 의 K/V 를 다음 호출에 재사용 → decode 속도 향상. HF 의 DynamicCache, vLLM 의 paged cache 가 구현.
RoPE (Rotary Position Embedding)
각 position 의 K/Q 에 회전 행렬을 곱해 position 정보를 인코딩. Llama / Mistral 사용. 회전 이라 invertible (RoPE shift 가능) + squared L2 norm 보존.
Pre-RoPE K
k_proj(hidden_state) 직후 (RoPE 적용 전) 의 K. Position 무관. 우리 구현 의 KVStore 저장 형식.
Hidden state
각 transformer layer 의 입력/출력 텐서 (1, S, hidden_size). Q/K/V 는 hidden_state 에서 projection.
Prefill
전체 input prompt 의 forward pass. 모든 position 의 K/V 가 한번에 계산됨.
Decode
한번에 1 token 씩 생성. past_key_values 사용.
Chunk
KV reuse 단위. 보통 document 1 개 또는 prefix/question 등 의미적 단위. 우리 의 Chunk 는 (text, token_ids, chunk_id) tuple.
Cache hit / miss
chunk_id 가 KVStore 에 있으면 hit (cached K/V 재사용), 없으면 miss (fresh forward).
Recompute ratio
전체 token 중 fresh recompute 할 비율. Paper default 0.15 (15%), Loong/wikimqa/samsum 은 0.18.
Top-K HKVD (High KV Deviation)
check_layer 에서 cached K vs fresh K 의 deviation 이 높은 상위 K 개 token. 이들 만 후속 layer 에서 fresh forward.
Check layer
HKVD 측정 layer. 보통 layer 1 (paper default). Phase 8 multi-check schedule 은 다중 layer 가능.
Sparse forward
check_layer 이후 일부 (top-K) position 만 forward. nontop position 은 cached K/V 그대로 두고 결과적 으로 attention 의 key/value 만 제공.
F1 (token-level)
predicted text vs gold answer 의 token id (tokenizer.encode 후) overlap precision/recall harmonic mean. Paper convention.
Paired bootstrap CI
per-example F1 차이 (method A - method B) 의 1000 회 bootstrap → 95% percentile interval. CI low > 0 이면 통계적 유의.
Eager attention
HF 의 명시적 (Q × K^T) softmax matmul 구현. bit-exact 검증 가능 but 메모리 O(S²) → long context OOM.
SDPA
torch.nn.functional.scaled_dot_product_attention. Flash / memory-efficient kernel 자동 선택. O(S²) score matrix 명시 materialize 회피.

9. 현재 구현 의 검증 상태

검증된 것
  • RoPE 재적용 비트 등가 (commit de6d818): fuse_full_reuse 후 K 가 정확히 fused position 의 post-RoPE 임을 5 layer × 2 chunk 에서 diff=0.000e+00 확인.
  • fuse_selective_lmc_parity CPU 단위 테스트 8/8 PASS: tests/test_fusor_lmc_parity.py 가 (1) boundary shortcuts, (2) past_key_values full-length, (3) non-HKVD K = cached RoPE-shifted (bit-exact <1e-5), (4) 마지막 position force-include, (5) pre-check layer 가 full_recompute 와 비트 등가, (6) legacy 와 다름.
  • HKVD 수식 LMCache 와 등가: docs/notes/lmcache-1to1-comparison.md §2.2 — squared L2, fp32 cast, dim sum 모두 일치.
  • Top-K 선정 LMCache 와 등가: §2.3 — int(N*r), max(1), topk, sort ascending 동일.
  • HF DecoderLayer kwarg 버그 수정: 4.49 는 past_key_value (singular) 사용. plural 로 호출 시 cache 비어 있음 → 수정 완료.
  • Quality 결과: Phase 6c Mistral (200) PASS, Phase 7c Llama (200) FAIL (모델 의존성), Loong Llama (50) CB 우위 (+0.03 F1, prefill 48% 빠름), HKVD boundary enrichment 3.13x.
부분 검증
  • fuse_selective (legacy) 와 fuse_selective_lmc_parity 의 F1 차이 거의 0 (Mistral Δ=−0.004, Llama Δ=+0.0001) — 두 알고리즘 모두 LMCache "수식 등가" but 의미는 다름. 자세한 비교는 docs/notes/lmcache-1to1-comparison.md.
  • SDPA path 의 sparse attention: CPU 단위 테스트 PASS, GPU 의 정확성 추가 검증 필요 (causal mask K dim slice 가 SDPA 의 내부 처리와 일관 인지).
  • LMCache (vLLM) 바이너리 와의 비교: 인프라 부재 로 직접 prefill 결과 비트 비교 불가. 수식/단계 등가성 으로 우회 검증.

리스크

  • SDPA 가 내부적으로 사용하는 kernel (flash / memory-efficient) 이 GPU/CUDA 버전 에 따라 다른 결과 가능 — bit-exact 비교 시 주의.
